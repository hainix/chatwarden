### Task 1: The matcher no longer ships obscenity's English list (issue #8)
- `packages/matcher/src/matcher.ts` imports `englishRecommendedTransformers` from the `obscenity` root. That root also loads
  `preset/english.js`, which holds `englishDataset`.
  - Import only what the matcher uses, from paths that do not load the preset (check `obscenity`'s `exports` map; deep `dist/...`
    paths only if exported).
  - Or rebuild the same transformer list from obscenity's exported transformer factories, in the same order and with the same
    options as `englishRecommendedTransformers` (read obscenity's source for them).
  - Matching behaviour must not change.
- **Tests:**
  - `scripts/browser-bundle.test.ts` bundles `@chatwarden/matcher` for the browser and asserts the output contains no
    `englishDataset` and none of a few distinctive non-slur marker words from obscenity's English list. Choose markers from its
    whitelist or phrase metadata, never slurs; or detect the preset module's file path in the esbuild metafile.
  - The existing matcher tests and parity fixtures stay green, unchanged.
  - Add a test that the transformer pipeline gives identical output to obscenity's preset on a table of tricky inputs: leet,
    confusables, repeats, spacing.
- Do not touch `site/`. Task 4 removes the site's workaround plugin.

### Task 3: hub-react: a refresh handle, and the settings and admin screens load on demand
- **The refresh handle.**
  - `<Hub>` gains an `onController?: (controller: HubController) => void` prop, marked `@experimental`. It is called once the
    controller exists, and again if it is replaced.
  - The headless controller gains `refresh(): void`, marked `@experimental`, which polls the change token now. It only reads; it adds
    no audit beyond what a normal poll does.
  - The site demo (`site/src/demo`) replaces its synthetic `visibilitychange` nudge with `controller.refresh()`, and its tests
    follow.
- **Load on demand.**
  - These screens become `React.lazy` with a quiet skeleton fallback: Terms, Blocked, Rule gaps, Audit, Guide, the Settings screens
    (Steps and ladder, Reporting) and All actions. The pieces of the same names lazy-load the same way.
  - The main bundle's gzip size must drop measurably. State it before and after, and lower the size budget to the new size plus
    about 5%.
  - Server rendering (`renderToString`) of `<Hub>` still works, and the React 18 smoke still passes.
  - hub-element's single-file bundle must stay one file: the bundler inlines dynamic imports when splitting is off. Verify it, and
    say so.
- **Tests:**
  - Each lazy screen renders after navigation, in Simple and Detailed.
  - The skeleton shows while loading.
  - A screen failing to load shows the hub's error block with Try again.
  - The handle is called, and `refresh` triggers exactly one change-token read.
  - The API lock snapshot is updated.
