# AI levels 1 and 2: Read and Recommend (Implementation Plan)

> **For agentic workers:** use superpowers:subagent-driven-development. One implementer per task, a review per task, a whole-branch
> review at the end. Steps are test-first: write the failing tests, see them red, then make them green. Run targeted tests only;
> never a full suite.

**Goal:** an owner can turn on AI level 1 (Read) or level 2 (Recommend) per game in the hub. Each new report gets one cheap,
async, fail-soft read from a pluggable `ModerationAI`. The read ranks the queue and sits on the case card (level 1). At level 2 the
decision bar is pre-filled from it and one key accepts it. Every human decision is recorded against the AI's draft. Moxgate runs
it on Claude Haiku 5.5 (`claude-haiku-5-5`) at about $0.0003 per report. Levels 3 and 4 are designed for (seams) and not built.

**Architecture:**
- `@chatwarden/core` gets a provider-free `ai` module: the `ModerationAI` interface, the static output schema and its hand-written
  validator, redaction, line choice, the safe prompt, the input hash, the ceilings, the worker (queue, sweeper, retries, budget,
  breaker), agreement and the casebook. No network, no dependency, no `node:` import.
- Optional `Store` methods (memory and SQLite migration 20) hold reads and outcomes. `createChatwarden({ ai })` wires `cw.ai`; the
  level is a new `ai` section of the policy layer (owner-editable, default 0).
- `@chatwarden/http` serves the read on the report page and a brief in queue summaries, plus status and "read again".
- `@chatwarden/hub-react` shows the strip, the pre-fill, the accept key and the Settings section.
- The Anthropic adapter is a private workspace, `examples/ai-anthropic`, copied or vendored by adopters. **No new npm package is
  published in this release** (see Release).

**Spec:** `docs/design/2026-11-11-ai-levels-1-2.md` (section numbers below refer to it). Also binding:
`docs/design/2026-11-10-hub-workbench-and-teams.md` ("Human decisions teach the AI"),
`docs/design/2026-11-10-editable-ladder-and-roadmap.md` (appeals, the false-positive rate), `docs/design/2026-11-09-moderation-standards.md`
(conduct levels, `aiContext`), and the public promise in `site/src/content.ts` (`LEVELS`, `CEILINGS`).

## Global Constraints
- Rules from `AGENTS.md` and `CLAUDE.md`: Apache-2.0 and DCO (`git commit -s`), ESM, `erasableSyntaxOnly`, every time from the injected
  `Clock`, synthetic terms only (zorbak, vlemmo, quissel, drakkuun, fenrisk, tarvo, snerp, glarn), test-first, targeted runs only,
  `npm run lint` and `npm run typecheck` before every push. With more than one agent in the worktree: commit by pathspec, `git add`
  new files first.
- `@chatwarden/core` stays browser-safe and dependency-free: no `node:` import (use `sha256Hex` from `crypto.ts`), no SDK, no
  `fetch`. Its browser bundle must not grow: the AI module is tree-shakeable, and `scripts/browser-bundle.test.ts` gains an
  assertion that the hub's bundle holds none of it.
- No identifier in anything sent to a provider or returned to a player: no subject id, staff ref, client key, account id, IP, hash,
  handle, seat id, room id or tag. A test renders prompts for generated reports and asserts none of these strings appear.
- The AI never writes a sanction, a strike, a mute or a notice. An ESLint `no-restricted-imports` rule forbids
  `packages/core/src/ai/**` from importing `decide`, `sanctions`, `strikes`, `mutes` and `notices`; `scripts/eslint-ban.test.ts` proves
  the rule fires.
- Ceilings hold in code, not by convention (design section 8): the one-key accept never pre-fills a ban, an area ban or more than 24
  hours (`AI_MAX_PREFILL_MS`); a recommendation to uphold or note needs a cited line by the reported person; flags, mutes and counts
  never reach the model.
- No test uses the network or a key. Every AI test uses `createFakeModerationAI`.
- UI (CLAUDE.md): every string through `t()`, colour only where it means something (the AI strip is neutral with a dashed outline; the
  Accept button is the blue next action), check in a real browser at desktop and 360 px, light and dark.
- Anthropic facts for the adapter come from the claude-api skill, not memory (Task 11 lists them). Never guess an SDK name: read the
  installed `@anthropic-ai/sdk` types.
- Privacy of the plan itself: nothing outward. No push, no publish, no tag, no site deploy without the maintainer's go-ahead.
- Branch `ai-levels`, worktree `C:\dev\chatwarden-wt\ai`.

## Review Focus
- **The ceilings.** Search for every path that could write a sanction from the AI module (there must be none), and for the pre-fill
  cap in the hub. Try to break `assertWithinCeilings` with a 25-hour restriction, an area ban, a ban and a no-own-line evidence set.
- **Fail-soft.** With the fake AI throwing, hanging, refusing, returning garbage and exceeding budget, `submit`, the queue, the case
  page and `decide` behave exactly as with the AI off, and the player's ack never waits for a model call.
- **Nothing identifying in the prompt**, and the same input always giving the same bytes for the stable part (cache safety).
- **Store parity.** The memory store and SQLite agree on the new contract suite, including the lease, `UNIQUE`, spend and purge.
- **The hub stays clean.** The always-visible additions are the strip, the labelled pre-fill, the Accept key and one queue chip;
  everything else sits behind the AI details menu or the Settings Advanced disclosure. Check the Simple mode card.
- **Agreement is computed on the server**, never from a client claim.
- **Releases.** No new published package; peer floors raised on purpose; `examples/ai-anthropic` is ignored by changesets and absent
  from the publish list.

### Task 1: The contract: types, output schema and validator, ceilings
Pure code in `packages/core/src/ai/`. Design sections 3 and 8.
- **Files:** `types.ts`, `schema.ts`, `validate.ts`, `ceilings.ts`; exports added to `src/index.ts` (marked `@experimental`);
  tests in `packages/core/test/ai/contract.test.ts`, `schema.test.ts`, `validate.test.ts`, `ceilings.test.ts`.
- **Interfaces:** `ModerationAI`, `AIReadInput`, `AIReadResult`, `AIUsage`, `AIRead`, `AIExample`, `AIError` (a class with
  `kind: 'retryable' | 'fatal' | 'declined' | 'timeout'`), `AI_PROMPT_VERSION = 1`,
  `AI_OUTPUT_SCHEMA` (a frozen JSON Schema object: `additionalProperties: false` on every object, `enum`s, no `minLength`/`maximum`,

  `AI_MAX_PREFILL_MS = 24 * 3_600_000`, `AI_MAX_KIND`, `assertWithinCeilings(step, evidence)`, `automationAllowed(person)` (returns true).
- **Behaviour:** validation downgrades, it does not guess: a recommendation to uphold or note whose cited lines include none by the
  reported person becomes `unclear` with the code `no_own_line`; an unknown rule, an unknown enum, an unsent line ref, a summary
  over 160 characters or holding a URL, markdown or a `P#` alias, more than 5 evidence refs, an extra key, a wrong type: `ok: false`.
  `bad_faith` is not a valid recommendation verdict.
- **Tests (names):**
  - `accepts a complete valid read`; `accepts a read with a null recommendation`
  - `rejects an unknown severity`; `rejects an unknown confidence`; `rejects a rule that is not active`; `accepts the rule "uncovered"`
  - `rejects an evidence ref that was not sent`; `rejects more than five evidence refs`; `rejects duplicate refs by collapsing them`
  - `rejects a summary over 160 characters`; `rejects a summary with a link`; `rejects a summary that names an alias`; `rejects markdown headings in a summary`
  - `rejects extra keys`; `rejects a non-object, an array, null and a string`
  - `rejects the verdict bad_faith`; `downgrades uphold to unclear when no cited line is by the reported person`
  - `the schema is static and carries no rule number or line ref`; `every schema object forbids additional properties`
  - `assertWithinCeilings refuses a ban, an area ban, 25 hours, no own line`; `accepts a warning, a note, a 24 hour chat restriction`
  - `a result type cannot carry an outcome` (type-level test with `expectTypeOf`)

### Task 2: Redaction, aliasing and line choice
Design section 8. Pure.
- **Files:** `packages/core/src/ai/redact.ts`, `lines.ts`; tests `packages/core/test/ai/redact.test.ts`, `lines.test.ts`.
- **Interfaces:** `redactText(text: string, handles: readonly string[], aliasOf: (h: string) => string | null): string`;
  `chooseLines(report: ReportRecord, opts?: { max?: number }): { lines: ChosenLine[]; truncated: boolean; people: AIPerson[]; reportedLine: string | null }`
  where `ChosenLine = { ref: 'L1'..; lineId: string; secondsIn: number; who: 'P1'..; text: string; blocked: boolean; byReported: boolean }`.
  The `ref` to `lineId` map is returned so the service can map an answer back; the lines handed to the adapter carry refs only.
- **Behaviour:** `P1` is the reported person, `P2` the reporter, others `P3...` by first appearance. At most 40 lines in time order:
  the reported person's latest 20, then 12 before and 6 after the pointed-at line, then the nearest others. Lines whose audience
  excludes the reporter are dropped. Seconds are relative to the first chosen line. Control, bidi and zero-width characters are
  removed. Placeholders: `[email]`, `[phone]` (7 or more digits, spaced or dashed), `[ip]` (v4 and v6), `[link]` (URLs, bare domains with
  a path, invite links), `[tag]` (`name#1234`), `[mention]`, `[token]` (hex or base64-like runs of 20 or more). The note is redacted and cut to 300
  characters without splitting a surrogate pair.
- **Tests (names):** table-driven, with variants and edge cases.
  - `replaces every handle with its alias, whole token, any case`; `does not replace a handle under 3 characters inside a longer word`;
    `replaces a handle inside another player's line`; `handles with regex characters are literal`
  - `placeholders: email, phone with spaces and dashes, ipv4, ipv6, url, invite link, name#1234, mention, long token`;
    `a sentence with no personal data is unchanged`; `a doxxing line keeps a [phone] placeholder, not the number`
  - `strips zero-width and bidi characters`; `collapses whitespace`; `cuts the note at 300 without splitting a surrogate pair`
  - `keeps at most 40 lines`; `keeps all of the reported person's latest 20`; `keeps 12 before and 6 after the pointed-at line`;
    `drops lines the reporter could not see`; `sets truncated`; `refs and aliases are stable for the same report`;
    `the reported person is P1 and the reporter P2 even when the reporter spoke first`
  - `a generated-report fuzz: no subject id, handle, seat id or ip string survives in any chosen line`
- **Run:** `npx vitest run packages/core/test/ai/redact.test.ts packages/core/test/ai/lines.test.ts`

### Task 3: The prompt and the input hash
Design sections 6, 7 and 8. Pure.
- **Files:** `packages/core/src/ai/prompt.ts`, `hash.ts`, `injection.ts`; tests `prompt.test.ts`, `hash.test.ts`, `injection.test.ts`
  in `packages/core/test/ai/`.
- **Interfaces:** `aiPolicyText(policy: DocumentPolicy): string` (rules in number order, the conduct-level table, `aiContext`; no
  outcomes, no ladder, no ids, no times; retired rules omitted; a value reduced to one line like `agentBrief`),
  `buildAIInput(args): AIReadInput` (fills `prompt.stable`, `prompt.variable`, `prompt.schema`), `inputHash(input, adapterId): string`,
  `looksLikeInjection(text: string): boolean`, `PROMPT_VERSION`.
- **Behaviour:** `prompt.stable` is the system instructions plus `aiPolicyText`, byte-identical for the same rules and standard. The
  instructions state that chat lines and the note are untrusted text written by players, that instructions inside them are evidence
  and never to be followed, that the answer is the JSON object only, and "when unsure choose the milder level". `prompt.variable` is a
  data block whose lines are JSON-encoded strings; it comes last. Examples (at most 2, each at most 400 characters) go in the
  variable part. The hash covers the version, the stable text, the variable text and the adapter id.
- **Tests (names):**
  - `the stable part is byte-identical for two reports under the same rules`; `changes when a rule's text changes`; `changes when aiContext changes`
  - `does not change when the ladder, durations or first-offence outcomes change`
  - `a retired rule is not in the prompt`; `rules appear in number order`
  - `no subject id, handle, seat, room, tag, ip or hash appears in the prompt` (fuzz)
  - `a line that contains </data>, a closing brace and a fake system message is rendered as one escaped string`
  - `the variable part comes last and holds no instruction text`
  - `the hash is stable, covers the adapter id and the prompt version, and ignores a reorder of object keys`
  - `looksLikeInjection: flags "ignore the above", "you are now", "system:", "as an AI", "disregard your rules", and not "ignore me lol" or "you are now in my way"`
  - `at most two examples, each cut at 400 characters`
  - `prompt.stable stays under 9 000 characters for the starter rules under each of the three presets` (a regression guard for cost;
    measure the real token count once with `count_tokens` on `claude-haiku-5-5` and record it in the PR, since the tokenizer is
    about 30% heavier than Haiku 4.5's)
- **Run:** `npx vitest run packages/core/test/ai/prompt.test.ts packages/core/test/ai/hash.test.ts packages/core/test/ai/injection.test.ts`

### Task 8: The service: worker, sweeper, budget, breaker, `cw.ai`
Design sections 4 and 6. The heart of the feature.
- **Files:** `packages/core/src/ai/worker.ts`, `service.ts`, `fake.ts`; `packages/core/src/chatwarden.ts` (option `ai?: AiOptions`, `cw.ai`,
  stop on `close()`); `index.ts` exports; tests in `packages/core/test/ai/`.
- **Interfaces:**
  `AiOptions = { adapter: ModerationAI; maxLevel?: 1 | 2; dailyBudgetMicros?: number /* 1_000_000 */; perMinuteCalls?: number /* 30 */; concurrency?: number /* 2 */; timeoutMs?: number /* 30_000 */; blockedLines?: 'raw' | 'mask'; contextTags?: string[] }`;
  `cw.ai = { level(): 0|1|2; status(): AiStatus; read(reportId): AiReadView | null; readAgain(reportId, actor): Promise<AiReadView | 'pending' | 'budget' | 'off'>; briefs(reportIds): Map<string, AiBrief>; stats(q): AiStatsView; close(): void }`.
  `AiStatus = { available: boolean; level: 0|1|2; maxLevel: 0|1|2; state: 'ok' | 'paused_budget' | 'unavailable' | 'off'; spentMicros: number; capMicros: number; day: string; reads: number; cacheHitRate: number | null }`.
  `createFakeModerationAI(script)` where a script is a function or a queue of `{ output } | { error: AIError } | { hang: true } | { usage }`.
- **Behaviour:**
  - Subscribes to `report.created` and only enqueues (no await, no store read) so the ack never waits. A sweeper on a timer using
    the injected clock (`setInterval` with `unref`, as retention does) enqueues unread open reports (newest first, 20 per tick) and due
    retries. Level 0 does nothing at all: no queue, no store read.
  - A job: build the input (Tasks 2 and 3), compute the hash, `reserveAiRead` (return if it already exists), check the breaker, budget
    and per-minute cap, call `adapter.read` with an `AbortSignal` deadline, validate, map refs to line ids, `completeAiRead`, and audit
    `ai.read` once per terminal outcome. `declined` and `invalid` are not retried (invalid once). `fatal` opens the breaker.
  - Budget: `aiSpendSince(startOfUtcDay)` plus the in-flight estimate; at the cap jobs are marked `skipped` and nothing is called.
  - The effective level is `min(policy.ai.level, maxLevel)`; no adapter means 0. A stale read (the stable prefix hash differs from the
    one now) is flagged `stale` in the view and queued for re-read only when a case is opened (`readAgain` or the case page) or by the
    sweeper when idle, under the budget. A reporter follow-up changes the hash and queues one read.
  - `read()` shows the recommendation only at level 2 (the view has `recommendation: null` at level 1); the stored row always has it.
  - `createChatwarden({ ai })` with a store that lacks the AI methods throws a plain error at creation.
- **Tests (names), all on the fake and the memory store with a manual clock:**
  - ack path: `submit resolves before the adapter is called`; `submit resolves while the adapter hangs`
  - `level 0 never calls the adapter and never reads the AI tables`; `level 1 stores the recommendation but read() hides it`; `level 2 shows it`
  - `the same report twice calls the adapter once`; `a changed rule text marks the read stale and does not re-read all open reports`;
    `opening a stale case re-reads once`; `a ladder change does not mark anything stale`; `a reporter follow-up queues exactly one new read`
  - `retryable error: retried at 1 minute then 10 minutes, then given up after three attempts`; `fatal opens the breaker and a probe closes it after 5 minutes`;
    `declined is stored and not retried`; `an invalid answer is stored once as invalid with a code`; `a timeout aborts the signal`
  - `five consecutive failures open the breaker`; `while open no adapter call happens and the queue and decide work`
  - `the daily cap stops calls and marks reads skipped; the next UTC day resumes`; `spend survives a new service instance on the same store`;
    `the per-minute cap defers jobs`
  - `two services on one store: the lease lets exactly one call the adapter`
  - `the sweeper picks up an unread open report after a restart, newest first, at most 20`; `turning the level from 0 to 1 fills the open queue gradually`
  - `ceilings: a fake that recommends upholding with no own line is downgraded to unclear`; `an answer citing a line ref that was not sent is invalid`
  - `no file in core/src/ai imports decide, sanctions, strikes, mutes or notices` (a test that reads the folder's import lines; Task 17 adds the ESLint rule)
  - `ai.read audit row: actor, null role, report target, no text`; `createChatwarden with a store lacking the AI methods throws`
- **Run:** `npx vitest run packages/core/test/ai/worker.test.ts packages/core/test/ai/service.test.ts packages/core/test/ai/budget.test.ts packages/core/test/ai/breaker.test.ts packages/core/test/ai/ack.test.ts`

### Task 9: Agreement, the casebook, examples and the decide integration
Design section 11.
- **Files:** `packages/core/src/ai/agreement.ts`, `casebook.ts`; `packages/core/src/decide.ts` (an optional `ai?: { readId: string; accepted: boolean }`
  on the decision input; the outcome row is written in the same store transaction as the decision; a replay writes nothing);
  `packages/core/src/ai/service.ts` (`markReversed`, `dontTeach`, `stats`, `examplesFor`); tests `agreement.test.ts`, `casebook.test.ts`, `decide-ai.test.ts`.
- **Behaviour:** `agreementOf(read, decision): { agreement: 'agree'|'override'|'none'; detail }` is pure (design section 11). The read used is the one named by

that already exist on npm. **No new npm package is published in this release.** That is the design: npm trusted publishing (OIDC) is

adapter ships as the private workspace `examples/ai-anthropic`, copied by adopters, exactly as `examples/tiny-chat` is not published.

6. A dry run: `gh workflow run release.yml -f dry_run=true --ref ai-levels`.
7. Merge when CI is green. **Tag and push only on the maintainer's go-ahead.** The release then publishes the ten through OIDC, with provenance.

### If the owner later wants `@chatwarden/ai-anthropic` as a package
This is the one place the owner must act by hand. A new package cannot be published through OIDC, and a Trusted Publisher can only be added to a
package that already exists on npm. In order:
1. In a branch: `git mv examples/ai-anthropic packages/ai-anthropic`; rename to `@chatwarden/ai-anthropic`; remove `private`; add `publishConfig.access: public`,
   the repository fields and `files`; make `@chatwarden/core` a peer (`^0.1.5`) and `@anthropic-ai/sdk` a peer (the range the adapter was tested on). Update
   the eleven-package lists: `PUBLISH_ORDER` in `scripts/publish-order.mjs` (after core), `scripts/manifests.test.ts`, the comments in `release.yml`, `RELEASING.md`,
   `scripts/smoke`, `scripts/check-pack.mjs`; remove it from the changeset `ignore`. It joins the fixed version group.
2. **Owner, once, by hand:** from a clean checkout of the commit that will be tagged, signed in to npm with 2FA as a member of the `@chatwarden` scope,
   publish the package at the group version: `npm publish --access public --workspace @chatwarden/ai-anthropic`. (No CI is involved; this first version has no
   provenance statement.)
3. **Owner, on npmjs.com:** open the package, Settings, Trusted Publisher, GitHub Actions; repository `hainix/chatwarden`, workflow `release.yml`. Check npm's
   current screens, they move.
4. Tag as usual. The release workflow skips any package whose exact version is already on npm (the one just published by hand) and publishes the other ten through OIDC. From
   the next release the new package publishes through OIDC too. Do not restore `NPM_TOKEN`.
5. Do steps 2 and 3 before the tag, never after: a tagged release that includes an unpublished, unconfigured package fails on that package.
