# The chat box and the room broadcaster (the release after 0.1.6) (Implementation Plan)

> **For agentic workers:** use superpowers:subagent-driven-development. One implementer per task, a review per task, a whole-branch
> review at the end. Steps are test-first: write the failing tests, see them red, then make them green. Run targeted tests only;
> never a full suite.

**Goal:** a game with no chat adds moderated chat in minutes. `@chatwarden/http` gains a room broadcaster and four routes (a Server-Sent
Events stream down, `POST` up) that put every line through `cw.chat.accept`, keep a bounded in-memory history for late joiners, show a
refusal only to its author, and resolve report and mute from a line. `@chatwarden/player-react` gains `<ChatBox>` and `sseTransport` at a
new lazy subpath, reusing `ReportDialog`, `RestrictedChatLine` and `NoticeQueue`. tiny-chat gains a browser page that uses them.

**Architecture:**
- `@chatwarden/http` gets `src/chat/` (`wire.ts`, `sse.ts`, `history.ts`, `broadcaster.ts`, `routes.ts`, `index.ts`), a shared
  `src/limiter.ts` (the names limiter, moved), and `KitResponse.stream` handled by `toExpress`. New subpath `@chatwarden/http/chat`,
  browser-safe (no `node:` import), also exported from the root.
- `@chatwarden/player-react` gets `src/chat/` (`wire.ts`, `sse.ts`, `state.ts`, `transport.ts`, `ChatBox.tsx`, `Composer.tsx`,
  `LineOptions.tsx`, `ChatOptions.tsx`, `index.ts`), `src/chat.css`, `player.chat.*` words in `i18n.ts`. New subpaths
  `@chatwarden/player-react/chat` and `/chat.css`. The main entry does not import any of it.
- `@chatwarden/core` is not touched. No store change, no migration, no peer floor rises.
- `examples/tiny-chat` gets the HTTP chat beside its WebSocket protocol and a browser page.

**Spec:** `docs/design/2026-11-12-chat-box.md` (section numbers below refer to it), including its closing Rulings section. Also binding:
`docs/design/2026-11-09-product-scope.md` section 10, `docs/design/2026-11-10-hub-simple-mode-and-embedding.md` (adopt at any depth),
and for pacing words `docs/design/2026-11-12-flood-control-and-signals.md` (sections 4.3 and 4.7).

## Global Constraints
- Rules from `AGENTS.md` and `CLAUDE.md`: Apache-2.0 and DCO (`git commit -s`), ESM, `erasableSyntaxOnly` (no parameter properties, no enums),
  every timestamp from an injected clock (the `now` option; no `Date.now()` call in package code beyond the `options.now ?? Date.now`
  default `playerRoutes` already uses), synthetic terms only in code, tests and docs (zorbak, vlemmo, quissel, drakkuun, fenrisk, tarvo,
  snerp, glarn; player names in examples are these too), test-first, targeted runs only, `npm run lint` and `npm run typecheck` before
  every push. With more than one agent in the worktree: commit by pathspec, `git add` new files first. Branch `chatbox`, worktree
  `C:\dev\chatwarden-wt\chatbox`.
- **Sequencing.** Neither flood control (branch `flood-signals`) nor AI levels (0.1.6, `ai-levels`) is required. **Step 0, before Task 1:**
  rebase on `main`; check whether `RefuseReason` in `packages/core/src/chat.ts` already contains `slow_mode`. If it does, Task 11 runs in
  full; if not, Task 11 waits and every other task uses the scripted facade described there. Nothing in this plan edits a file the
  flood plan owns except `packages/player-react/src/i18n.ts` (additive keys in a different area) and `packages/http/src/types.ts` (a new
  optional field); resolve a merge conflict by keeping both.
- **`@chatwarden/http/chat` is browser-safe:** no `node:` import (so `Buffer`, `crypto`, `http`, `stream` are all out), no `fetch`, no DOM.
  Seat ids use core's `makeHasher` and the platform `crypto.getRandomValues` for the salt. `scripts/browser-bundle.test.ts` proves it.
- **`@chatwarden/player-react` stays types-only toward the kit** (`static.test.ts`: no run-time import of core or http), imports no
  hub-react, injects no HTML, styles nothing inline, and puts every word in the catalog. The main entry (`src/index.ts`) reaches nothing in
  `src/chat/` (Task 9 pins it) and keeps its 10 KB gzip budget; the chat entry has its own budget (design 13.5).
- **Nothing identifies a player on the wire** (design ruling 7): no seat id, subject id, client key, hash, IP or account id in any frame,
  answer, header or log. Logs carry event names and error classes only (`safeWarn`, `ThrottledWarn`); never a line, name, room, seat or
  credential.
- **A refused line is never echoed** to anyone but its author, never stored in the ring, and never logged (ruling 4).
- **UI rule (clean core, power behind one door).** The always-visible UI is the list, the input and Send. Per-line options and Chat
  options are the only doors; no new always-visible badge, counter or toggle. Every string through `t()`. Colour only where it means
  something. Check in a real browser at desktop and 360 px, light and dark, for Tasks 9, 10 and 12.
- All new public names are `@experimental` in TSDoc and listed so in the READMEs until 0.2.
- Privacy of the plan itself: nothing outward. No push, no publish, no tag, no site deploy without the maintainer's go-ahead.

## Review Focus
Five failure modes no task's happy-path tests would otherwise exercise; each has its test in the owning task.
1. **A refused line escaping.** Text of a blocked, restricted, profanity-refused, length-refused or pace-refused line must not appear in any
   other stream, in the ring, in a later snapshot, in a log, or in the author's own answer. Tasks 4 and 12.
2. **Identifiers on the wire.** Seed distinctive client keys, account ids, IPs, subject ids and seat ids; none may appear in any frame,
   answer, header, SSE comment or log line, including error paths (a thrown `identify`, a bad body). Tasks 6 and 12.
3. **Lifecycle leaks.** Streams that close mid-write, clients that vanish with no close, slow readers, a reconnect storm, thousands of
   joins and leaves: timers cleared, seats released after the grace, every map back to zero, no write after close. Tasks 2 and 5.
4. **Late join and reconnect.** The snapshot must respect the joiner's mutes, be bounded in count and age (never older than the evidence
   window), merge on reconnect without duplicates or reordering, reset on a new epoch, and must not be read aloud as 50 new lines. Tasks 3, 7
   and 9.
5. **Hostile input in both directions.** A cross-site form or text/plain POST must not make a player speak; markup, `javascript:` strings,
   RTL overrides, 10 000-character words and zero-width spam in a line or a name must render as inert text and wrap at 360 px; a
   malformed or oversized frame must not break the reader. Tasks 6, 7 and 9.

### Task 5: The broadcaster: mutes, reports, state, limits, lifecycle
Design 6.2 (the rest), 8.2 (mutes), 11 (abuse limits), Review Focus 3. Needs Task 4.
- **Files:** `packages/http/src/chat/broadcaster.ts`; tests `packages/http/test/chat-mutes.test.ts`, `chat-report.test.ts`, `chat-lifecycle.test.ts`,
  `chat-state.test.ts`.
- **Behaviour:**
  - `mute({ lineId, on })`: resolves the author through `ring.byId` and the viewer's visibility; `cw.mutes.set(room, viewerSeat, authorSeat, on)`;
    writes `hide { ids }` (the author's lines in the ring) and `state` (the new `muted` list) to every stream of the viewer, nothing to anyone
    else. `mute({ ref, on })`: `ref` is a random 8-character token allocated per (room, seat) on first listing; accepted only when it names a seat in
    `cw.mutes.mutedSeats(room, viewerSeat)`. Muting oneself, an unknown line, or an unseated author returns `false`.
  - `muted` in `hello` and `state` is `cw.mutes.mutedSeats` mapped to the current members' `{ ref, name }`.
  - `report({ lineId, reason?, note? })`: line from the ring and visible to the reporter, else `{ ok: false, refused: 'not_found' }`; calls
    `cw.reports.submit({ roomId, reporterSeat, targetSeat, lineId, reason, note })` and returns `{ ok: true, remaining }` or `{ ok: false, refused,
    remaining? }`; never returns the report id; a rejected promise from the kit is `{ ok: false, refused: 'off' }` and is logged by class only.
  - `noticePending(subject)`: finds the seats whose `cw.rooms.subjectAt` equals the subject (merged aliases fold in) and writes `notices` and
    `state` (re-reading `cw.chat.restricted`) to those streams only.
  - Limits and lifecycle: `maxMembers` (a join over it is `{ refused: { reason: 'full' } }`), `maxStreamsPerMember`, `maxStreams` (each `full`);
    heartbeat re-armed through `schedule` and cancelled on close; a sink returning `false` `maxBacklog` times in a row is closed; a seat with no
    stream is `unseat`ed `seatGraceMs` after its last stream close or last request (every `session()` call refreshes it); an empty room and its
    ring are removed; `closeRoom` writes `bye room_closed`, ends the room's streams, calls `cw.rooms.close`; `close()` writes `bye shutdown`
    and clears every timer.
- **Tests (names):**
  - mutes: `a muted author's lines skip only the muter's streams and the muter's other tabs`; `the author's answer to send is unchanged and no frame about the mute ever reaches the author`
  - `hide removes the author's earlier lines from the muter's open streams; a later hello omits them; unmute by ref restores future lines`; `a ref from another player, another room or a stale seat is a no-op`; `muting yourself, an unknown line id and an aged-out line return false`
  - `muting persists in the kit: a new broadcaster over the same store still hides the author` (mute TTL is the kit's)
  - reports: `a report on a visible line files a kit report with the reporter's seat and the line's author as target and returns only remaining`; `unknown, aged-out and hidden lines are not_found`; `own line is the kit's self`; `the kit's refusals (duplicate, rate, suspended, off, reason_unknown) pass through by name`
  - `a body field naming a seat or reporter is ignored (the API has none)`; `a kit that rejects is { ok: false, refused: 'off' } and logs the error class only`
  - state: `noticePending writes notices and state to that person's streams only, including a merged alias`; `a sanction that lands while connected shows in the next hello and the next refusal even without noticePending`
  - lifecycle (Review Focus 3): `closing a stream cancels the heartbeat when it was the last`; `a sink that returns false maxBacklog times is closed; fewer times, not`; `seats are released seatGraceMs after the last stream and last session call, not before`; `10 000 joins and leaves leave stats() at zero rooms, members and streams`; `maxMembers, maxStreamsPerMember and maxStreams refuse the next with full`; `closeRoom ends only that room; close ends all and clears every scheduled timer (the fake scheduler has none pending)`
  - `a restart is a new epoch: two broadcasters over one cw have different epochs and a client can tell`
- **Run:** `npx vitest run packages/http/test/chat-mutes.test.ts packages/http/test/chat-report.test.ts packages/http/test/chat-lifecycle.test.ts packages/http/test/chat-state.test.ts packages/http/test/chat-broadcaster.test.ts`

### Task 7: Client wire, SSE parser and reducer (player-react)
Design 6.6, 7, 9. Pure; independent of the server tasks.
- **Files:** `packages/player-react/src/chat/wire.ts` (the copy of the wire types plus `readFrame(raw: unknown): ChatFrame | null`),
  `src/chat/sse.ts` (`createSseParser(onEvent: (event: { type: string; data: string }) => void): { push(chunk: string): void }`),
  `src/chat/state.ts` (`ChatState`, `ChatAction`, `chatReducer`, `initialChatState`); tests `packages/player-react/test/chat-wire.test.ts`,
